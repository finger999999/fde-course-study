第七课 · 原型开发

学习版说明：让方案”看得见”，同时守住 demo 的诚实边界。先立一条规矩：demo 跑通的是 UI，不是模型——把外壳当成”产品跑通了”去演示，就是骗客户。本课有全课唯一一条”一票警示”红线。

学习目标

一、三步流水线

/studio-design:design <输入>
  ① screenshot-to-pencil  → screens.pen     ⏸ 你确认
  ② pencil-to-openspec    → openspec/       ⏸ 你确认
  ③ openspec-to-code      → React/Next.js 代码
  • 可从任意阶段切入：给截图从①开始；给 .pen 文件从②开始；给 change-id 从③开始
  • ⚠️ 建议显式指定要跑哪一步，别赌工具猜对
  • 实测澄清：.pen 文件其实是明文 UTF-8 JSON，插件文档里的某些说法与本地实际文件不符——又是那句”别信文档，去看代码”
  • 设计令牌（颜色/字号等 token）是设计层的”口径单点”，和第六课 BRIEF 的数字单点是同一个思想

二、缺信息时的兜底约定（直接关系诚实边界）

工具生成代码时遇到缺的信息，会留 TODO 注释（比如”此处应接真实接口”）。

这些 TODO 就是你的 Mock 清单。别删掉它们——删了 TODO 不等于实现了功能，只等于你看不见了。

三、⭐⭐ demo 可信度三档（本课的灵魂）

你会说”我们的 demo 是 Mock”。但 Mock 不是一档，含金量差一个量级。 对比两个真实案例：

案例 A 案例 B
界面 47 个页面 11 个页面
AI 回答 Mock（关键词路由） Mock（正则分支 + 延时假装思考）
数据 真的——直接读 79 家机构的真实 CSV 全仿真——写死在代码里
分级 壳假 · 数据真 壳假 · 数据也假

你的三档自评

档 你的 demo 是 演示时必须说
A 壳真 + 数据真 + 模型真 （还没人到这一档）
B 壳假 + 数据真 “界面是原型，数据是客户真实数据，AI 回答是预设的”
C 壳假 + 数据假 “这是交互外壳，数据和 AI 回答都是演示用的，不是模型跑通”

说不出自己在哪一档 → 路演一票警示。 演示规定动作：先念 Mock 清单，再开始演。含糊带过不是撒谎，是”不说”——同样算触发。

四、实操要点

  • 产出 3–6 屏原型 + 诚实说明 + Mock 清单
  • 按交付模式分形态：模式一重”能用的应用”，模式二重”能过评审的演示”
  • 🔔 强烈建议做一屏”人工确认界面”（HIL 确认屏）：能把闸画出来的方案，客户才相信你真的想过责任归属
  • 常见翻车：目录前缀要人工对齐（工具不会自动加）；spec 文件要有规定的段落包裹；没实测过的链路要诚实标注”未实测”

五、同一条纪律的第四个场景

文号（第五/六课）、数字（第三课）、来源标注（第一课）、Mock 声明（本课）——四个场景是同一句判据的四次出现：

空缺可以补，编造无法挽回。

想一想：下周你拿这个 demo 去见客户，你会怎么说？那句诚实的”这部分是演示数据”，就是客户以后愿不愿意信你第二次的分界线。

自测

  1. demo 三档各是什么？你的 demo 在哪一档？演示时必须说什么？
  2. 为什么不能删代码里的 TODO？
  3. 三步流水线是哪三步，各有几个确认点？
