# 第一课 · FDE：是什么，为什么，怎么工作

> **学习版说明**：这是全课程的地基课。读完你应该能用大白话回答三个问题：FDE 到底解决什么问题、人和 AI 各自干什么、五天学习按什么流程走。

## 学习目标

- [ ] 说清什么是"交付断层"，为什么传统团队结构解决不了它
- [ ] 理解"一人公司（OPC）"的含义和它的边界
- [ ] 记住认知杠杆公式，知道 AI 真正改变了什么、没改变什么
- [ ] **硬指标：能复述 SOP 七阶段，并说出每阶段对应第几课**

## 一、交付断层：FDE 要解决的根本问题

想象一个典型项目的信息流：

```
客户 → 需求人员 → 设计人员 → 开发人员 → 交付人员
```

客户说"我的老人能被照顾好"。需求人员把它写成需求文档，设计人员画成蓝图，开发人员做成系统，交付人员交给客户。**每一棒交接，都有一部分"只在上一个人脑子里、没写进文档"的东西永久丢失。**

> **客户要的是结果，组织给的是工序。**

有人本能反应是"那文档写细一点不就行了？"——不行。因为断层不是某个人不认真，它是**工序制的结构性产物**：只要你把一件事切成四段交给四拨人，断层就一定存在，跟态度无关。

**FDE 的机制只有一句话：把需要跨四个人接力的判断链，压进一个人的头脑里连续走完。** 智能体（AI Agent）是这一个人的手脚，不是接力赛里的另一棒——它不接手判断，只放大执行。

⚠️ **一个常见误读要先掐掉：贯通 ≠ 求全。** FDE 不是"什么都自己做"，建模要服务于业务优先级。有项目把用户旅程建得巨细靡遗，结果返工——这个返工成本要记在"方法论用错了"的账上，不是"运气不好"。

## 二、FDE = 一人公司（OPC），但边界比能力半径更重要

FDE 一个人能调动智能体编队完成过去 5 人团队数周的活，所以叫"一人公司"。但**一人公司不是让你逞能，是让你清楚地知道自己什么时候必须叫人。**

### 边界判据三问（比背清单管用）

拿任何一件活，问三个问题：

1. **这件事需要一个身份才能做吗？**（比如去某机构取一份文件）
2. **这件事需要一个立场才能拍吗？**（比如某个阈值定多少，是权衡不是计算）
3. **这件事做错了谁负责？**

**只要有一个答案指向"人"，这活就在"必须人扛侧"；做错了能回退重跑的，在"可替侧"（可以交给智能体）。**

| 活 | 判定 | 原因 |
|---|---|---|
| 取一份需要人脉才能拿到的文件 | 人扛 | 需要身份 |
| 定一个影响速度的容错阈值 | 人扛 | 需要立场 |
| 整理 102 个业务事件 | 可替 | 错了能回退重跑 |
| 生成 7 个域的骨架 | 可替 | 错了能回退重跑 |

> **C1–C6（技术能力）可训练，C7（人的部分）只能筛选。** 一个只会往前冲、不知道边界的 FDE，比一个慢一点但知道边界的 FDE 危险得多——因为他会在查不到的地方编一个出来。

## 三、认知杠杆：AI 到底改变了什么

### 杠杆公式

```
产出 = 结构化能力 × 平台固化 × 模型算力
```

| 因子 | 谁提供 | 缺了会怎样 |
|---|---|---|
| **结构化能力** | **人**（把模糊意图压成可执行结构） | 模型再强，也只是把你的模糊放大成一百页的模糊 |
| **平台固化** | 工具链（如 Astra Studio） | 每个项目从零起，方法留在个人脑子里 |
| 模型算力 | 大模型 | —— |

> **难听话：三个因子里，唯一可以用钱买到的是模型算力，而多数人以为它是全部。**

### Vibe Coding 的真相

有人用 AI 辅助 3 小时手搓了一个本体引擎原型。他复盘"AI 到底干了多少活"：

| AI 能干的 | AI 不能干的 |
|---|---|
| 给了明确规格后，把伪代码变 Python | 规则该在写入前还是写入后执行？ |
| 处理文件读写、生成测试 | 日志存快照还是只存变化？ |
| **共同特征：给明确规格，快速生成** | **共同特征：工程判断，不是编码问题** |

> **AI 能把"想清楚的事"快速变成代码，但不能代替"想清楚"这件事本身。**

没有蓝图的 Vibe Coding 会失控——它会很流畅地生成一堆自洽的、错的东西。你省下的思考，最后都要用返工还回来。

## 四、别人家怎么落地（学的是"来源纪律"）

Palantir 是 FDE 岗位的原产地；Delta、OpenAI、Anthropic 等也有类似实践。但这一节真正要教的不是八卦：

> **当你要把外部实践当作论据时，你标注来源的严谨程度，等于你专业的可信程度。**

很多网传数字（薪资、成功率、百分比）属于二手甚至未获证实的信息。**如果你只抄一个数字不写口径，你就在制造错误。** 引用外部数据时，分清三档：一手可核验 / 二手转述 / 未获证实——各标各的。

## 五、能力模型 C1–C7

| 维度 | 内容 | 在哪练 |
|---|---|---|
| C1 认知萃取 | 事件风暴 · 画像 · 旅程 · 热点 | 第四课上 |
| C2 结构建模 | DDD 限界上下文 + 五要素 | 第四课下/第五课上 |
| C3 风险设闸 | 人工介入点（HIL）设点原则 | 第五课下 |
| C4 合规治理 | 依据取证 · 诚实边界 | 第五课下/第六课 |
| C5 商业建模 | 投资 / 收入 / IRR | 第六课 |
| C6 交付物工程 | 并行写作 · 装配质检 | 第六/七课 |
| **C7 人的部分** | 客户关系 · 责任承担 · 价值判断 | **只能筛，不能训** |

**三级能力锚**：Lv.1 见习（在指导下承接单一环节）→ Lv.2 胜任（独立完成认知侧全链条，交付物需一次复核）→ Lv.3 主理（主持项目、对客户承诺负责）。

> 多数人第一次会停在 Lv.1，这是正常的。**装作 Lv.2 才是危险的。**

## 六、⭐ SOP 七阶段（本课落点，硬指标）

| 阶段 | 干什么 | 对应课 |
|---|---|---|
| 立项 | 把客户模糊意图变成可接住的输入 | 第三课 |
| S1 认知萃取 | 事件 → 画像 → 旅程 → 热点 | 第四课上 |
| S2 结构收敛 | 事件归簇 | 第四课下 |
| S3 域切分 | 切限界上下文 | 第四课下 |
| S4 本体建模 + 设闸 | 五要素 → 编译 → HIL | **第五课（全课重心）** |
| S5 合规治理 | 挂依据 / 留占位 / 转取证清单 | 第五课下 + 第六课 |
| S6 交付物工程 | 并行写作 → 装配 → 导出 | 第六 + 七课 |
| S7 HIL 运行留痕 | 谁确认的、确认错什么代价 | 横切全程 |

**这条路上每一步都有一个"必须由人做的判断"。找到它，就是你要学的东西。**

## 三条贯穿全程的纪律

1. **产物没落盘就是没做**——每一步都必须真跑工具。
2. **案例只做标尺、不做模板**——照结构做，别抄数字。
3. **查不到的一律留占位、不编造**——这是结课路演的一票警示。
