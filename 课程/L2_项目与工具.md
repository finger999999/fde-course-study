# 第二课 · 项目与工具

> **学习版说明**：这一课做两件上路前的准备：认领一个贯穿五天的真实命题，装好全部工具并跑通工作区。今天不进入 SOP 的任何阶段——领到车，把油加满。

## 学习目标

- [ ] 写出一句话项目定义，并判定本组命题的交付模式（模式一/模式二）
- [ ] 说清九个插件各管哪一段、"产物即接口"是什么意思
- [ ] 避开安装环节的四个典型翻车点

## 一、为什么用真实命题，不用玩具题

**玩具题练不出 FDE。** FDE 的难点从来不是"会不会用工具"，而是**在信息不全、口径打架、有人反对的真实环境里做判断**。所以每个命题都带四样东西：客户背景、客户原话（模糊意图）、已知约束、以及故意埋的"查不到的项"（逼你练"留占位不编造"）。

**规则：命题一旦认领就不换。** 中途换题等于把前面所有产出作废。这本身就是一课：需求会变，但项目不会因为你觉得难就换一个。

### 一句话项目定义（当场写下来）

> 格式：给【谁】做一个【什么】，解决【什么错配/痛点】。
> 示例：给县域失能老人家庭做一个"助浴+喘息"上门服务调度与结算网络，解决"服务供给散在各机构、家属找不到、补贴走不通"的三方错配。

这句话第三课会被打回来重写好几次——现在写得糙没关系，**但必须写下来，它是后面所有产出的锚**。

## 二、交付模式判定（本课唯一有标准答案的判断）

这个判断第六课写财务语言时要用，判反了当场露怯：

| 问自己 | 模式一（Token 计费 SaaS） | 模式二（平台建设 + 运营） |
|---|---|---|
| 卖的是什么 | 一个能跑的 agent 应用 | 一套平台 + 一门生意 |
| 怎么收钱 | 按 token / 调用 / 席位 | 投建运 + 运营盘 + 多元收入 |
| 有没有运营盘 | ❌ 没有 | ✅ 有（站点、会员……） |
| 要不要写可研 | 通常不要 | 必须 |
| **财务语言** | **MRR · LTV:CAC · NRR** | **IRR · 回本周期 · NPV** |

**判据记忆法**：看它有没有"运营盘"（要持续经营站点/会员/服务网络）。有 → 模式二；纯卖应用 → 模式一。

## 三、工具全景：Astra Studio 九个插件

```
studio-core      工作区管理（init/status/promote）
studio-insight   业务分析六件套（画像/旅程/流程/画布/行为矩阵/机会） ← 第四课上
studio-planner   规划流水线（事件风暴→域模型→技能设计→骨架→填充）   ← 第四课下
studio-ontology  本体编译（五要素 → 可运行插件）                     ← 第五课
studio-docs      文档交付（蓝图/写作专家/并行写作/装配/导出）         ← 第六课
studio-platform  平台文档套件（脑图/技术设计/项目计划）               ← 第六课
studio-design    设计转代码（截图→.pen→openspec→React）              ← 第七课
studio-quality   插件校验 + 接线                                     ← 第八课
fund-review      采购报价优化 + 预审（选修）
```

### 必须现在建立的两个认知

**① 产物即接口**：工具之间不靠内存传参，**靠文件**。每个文件都是上一步的输出、下一步的输入。三个直接后果：随时可中断、每步可单独重跑、**可以人工改产物再继续**（模型给的结构不满意，你直接改文件）。

**② OAG ≠ RAG**：RAG 是"检索得准一点"；OAG（行动增强）是"**越权的结果根本生成不出来**"。防幻觉在执行层（本体约束），不在检索层。一句话：**LLM proposes, ontology enforces.**（第五课讲透）

### 平台 = 方法论的固化物

固化发生在三层：**工具层**（步骤顺序被固定，不用每次想先干哪个）→ **结构层**（产物形状固定，下游能直接消费）→ **纪律层**（什么不许做，由校验器强制执行）。

> **第三层最值钱：工具能省时间，纪律能防事故。而且纪律有个特点——它在你最想违反的时候生效。**

## 四、装工具：四个翻车点（全是实测踩出来的）

完整命令序列见完整版手册。这里只记**会坑你的四个点**：

1. **装完插件当前会话看不到新命令 → 重启客户端**。插件在会话启动时加载，装完不热更新。**别卸载重装——它根本没装失败**，反复重装只会越搞越乱。
2. **装不到 `studio-ontology` → 先跑 `marketplace update`**。它是后加进市场的，旧快照里没有。update 时打印的"cleaning up and re-cloning"是正常行为，不是报错。
3. **升级不能靠重装**：改版后必须 `marketplace update` + `plugin update`，再跑一次 `install` 无效；兜底用 `install --force`。
4. 两个仓库 URL（改名前后）指向**同一个 commit**，看到一个别慌，不是两个仓库。

装完初始化工作区 `/studio-core:init`，应得到 `studio/` 目录（config.yaml / changes/ / agents/ / archive/）。另需外部依赖：**pandoc（硬依赖，第六课导出必用）**、mermaid-cli 和 python-docx（软依赖，缺了只降级不阻断）。
